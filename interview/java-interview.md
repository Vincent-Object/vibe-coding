# Java 中高级开发者面试指南（面试官用）

> 面试时长：20-30 分钟 | 候选人画像：3-5 年 Java 开发经验 | 考察方向：综合

---

## 使用说明

共 **5 个模块**，每个模块 1-2 题，由浅入深。20-30 分钟内不一定每道都问到，根据候选人回答的深度灵活调整。每道题标注了「你听什么」和「红绿灯信号」，你只需要对照判断即可。

---

## 模块一：项目经历摸底（约5分钟）

### 问题 1

**"请挑一个你最近主导或深度参与的 Java 项目，说说项目背景、你负责什么、技术栈是怎样的。"**

**你听什么：**

这题不考技术深度，考的是他是不是**真正干过活**。

🟢 好的信号：能说出具体的业务场景（比如"电商订单系统""支付清结算"）；能清晰描述自己负责的模块而不是泛泛说"后端开发"；技术栈描述具体（比如"Spring Boot + MyBatis + Redis + RocketMQ，部署在 K8s 上"）；能说出系统的量级（日活、QPS、数据量级等）。

🔴 警惕信号：说不出具体项目或业务场景；技术栈只说"SSM"三个字母就没了；把团队成果说成自己的，追问细节时含糊。

### 问题 2（追问）

**"在这个项目中，你做过的最有技术含量的一件事是什么？"**

**你听什么：**

区分"参与者"和"核心贡献者"。

🟢 好的信号：能说出具体的技术挑战（比如"把接口响应从 500ms 优化到 50ms""设计了一套分布式锁方案解决并发超卖"）；有清晰的问题 → 分析 → 方案 → 结果的叙事结构；能说出为什么选这个方案而不是别的。

🔴 警惕信号：说"最有技术含量的事"只是"搭建了项目框架"或"写了 CRUD"；描述不出任何技术决策的过程。

## 模块二：Java 基础功底（约5-8分钟）

### 问题 3

**"HashMap 是 Java 里最常用的数据结构之一。你能说说它的底层实现原理吗？在什么情况下它会出问题？"**

**你听什么：**

这是 Java 面试的经典基础题，3-5 年经验**必须**答得好。

🟢 好的信号：能说出底层是**数组 + 链表 + 红黑树**的结构（JDK 8 之后链表长度超过 8 会转红黑树）；能解释 hash 冲突的处理方式；能说出**线程不安全**的问题——多线程下并发 put 可能导致数据丢失或死循环（JDK 7）；能提到替代方案如 **ConcurrentHashMap**；如果能说出扩容机制（容量翻倍、重新 hash）则更好。

🔴 警惕信号：只说"key-value 存储"就没了；不知道线程安全问题；完全不知道红黑树优化。

### 问题 4

**"Java 的线程池你用过吧？说说线程池的核心参数有哪些，以及你在实际项目中是怎么配置的？"**

**你听什么：**

并发是 Java 中高级开发者的核心能力，线程池是最实战的考点。

🟢 好的信号：能说出核心参数——**corePoolSize**（核心线程数）、**maximumPoolSize**（最大线程数）、**keepAliveTime**（空闲线程存活时间）、**workQueue**（任务队列）、**handler**（拒绝策略）；能说出不同队列的区别（LinkedBlockingQueue 无界队列、ArrayBlockingQueue 有界队列、SynchronousQueue 直接移交）；**关键加分项**：能说出为什么不推荐用 Executors.newFixedThreadPool 等快捷方式（因为默认用无界队列可能导致 OOM）；能结合实际业务场景说怎么配的参数。

🔴 警惕信号：只知道 Executors.newFixedThreadPool 这种用法，说不出底层参数；不知道拒绝策略；从没在项目中自定义过线程池。

## 模块三：框架与设计（约5-8分钟）

### 问题 5

**"Spring 的 IOC 和 AOP 你肯定天天用，能不能用大白话说说它们到底解决了什么问题？你在项目中用 AOP 做过什么？"**

**你听什么：**

Spring 是 Java 开发的基本功，这题考的是理解深度而不是背概念。

🟢 好的信号：**IOC** 能说清楚核心思想——对象的创建和管理不再由程序员自己 new，而是交给 Spring 容器，好处是解耦、方便测试和替换；**AOP** 能说清楚是"把通用的横切逻辑抽出来统一处理"；能举出 AOP 的实际应用（统一日志记录、权限校验、事务管理、接口耗时统计等）；如果能提到底层实现原理（动态代理：JDK 代理 vs CGLIB 代理）就更好。

🔴 警惕信号：只会背"控制反转""面向切面"但解释不清楚到底是什么；从没自己写过自定义 AOP；把 AOP 和拦截器混为一谈又说不出区别。

### 问题 6

**"假设你现在要设计一个接口，这个接口预计会被高频调用（比如每秒几千次），你在设计和编码时会考虑哪些事情？"**

**你听什么：**

这是一道综合性设计题，考察候选人的**工程化思维广度**。没有标准答案，看他能想到多少层面。

🟢 好的信号（提到的维度越多越好）：

- **缓存** — 热点数据放 Redis，减少数据库压力
- **数据库** — 索引优化、读写分离、分库分表
- **并发控制** — 限流（令牌桶、滑动窗口）、熔断降级
- **异步化** — 非核心逻辑用消息队列异步处理
- **接口设计** — 幂等性设计（防止重复提交）、合理的超时设置
- **监控** — 接口耗时监控、报警机制
- **代码层面** — 减少锁竞争、避免大事务、合理的连接池配置

🔴 警惕信号：只说"加缓存"一个维度就没了；完全没有限流和降级的意识；不考虑幂等性。

## 模块四：问题排查与调优（约5分钟）

### 问题 7

**"假设线上有一个服务，CPU 突然飙到 100%，你会怎么排查？说说你的步骤。"**

**你听什么：**

这是最实战的题目之一，直接考察线上问题的处理能力。

🟢 好的信号（有清晰的排查步骤）：

1. **先定位哪个进程** — `top` 命令找到 CPU 高的 Java 进程 PID
2. **再定位哪个线程** — `top -Hp PID` 找到具体的线程 ID
3. **看线程在干什么** — 线程 ID 转成十六进制，然后用 `jstack PID` 导出线程栈，搜索对应线程，看它卡在哪段代码
4. **分析原因** — 常见原因有：死循环、频繁 GC（可以用 `jstat` 看 GC 情况）、正则表达式回溯、锁竞争等
5. **验证修复** — 定位到代码后修复上线，持续观察

如果能提到用 **Arthas** 等在线诊断工具来辅助排查，加分。

🔴 警惕信号：完全没有排查思路，上来就说"重启服务"；不知道 jstack、jstat 这些基础命令；从没处理过线上问题。

### 问题 8（可选，时间充裕时问）

**"你遇到过内存溢出（OOM）的问题吗？你是怎么排查和解决的？"**

**你听什么：**

和上一题配合，考察 JVM 层面的实战能力。

🟢 好的信号：能区分不同类型的 OOM（堆内存溢出、方法区溢出、栈溢出等）；排查步骤清晰——先通过 `-XX:+HeapDumpOnOutOfMemoryError` 拿到堆转储文件，用 **MAT**（Memory Analyzer Tool）或 **VisualVM** 分析大对象和引用链；能说出常见原因（大集合未释放、数据库查询未分页返回了全量数据、第三方资源未关闭等）；能说出预防手段（代码审查、压测、监控告警）。

🔴 警惕信号：遇到 OOM 只会"加内存"；不知道堆转储分析工具；从没分析过内存问题。

## 模块五：架构思维与软素质（约5分钟）

### 问题 9

**"你们项目中有用到消息队列吗？用的哪个？为什么选它？如果消息丢了或者重复消费了怎么办？"**

**你听什么：**

消息队列是中高级 Java 开发者绑定的知识域，考察的是"知其然更知其所以然"。

🟢 好的信号：能说出用过什么（RocketMQ / Kafka / RabbitMQ 等），并说清楚**为什么选这个**（不是"大家都用"，而是基于业务场景的判断，比如"Kafka 吞吐高适合日志场景""RocketMQ 支持事务消息适合订单场景"）；**消息丢失**方面能从三个环节分析——生产端确认机制、Broker 持久化、消费端手动 ACK；**重复消费**能提到用幂等性来兜底（唯一ID + 去重表，或业务状态机判断）。

🔴 警惕信号：用过但说不出选型原因；不知道消息丢失和重复消费的处理方案；只停留在"发消息、收消息"的使用层面。

### 问题 10（收尾）

**"你在做技术选型或架构决策的时候，通常会考虑哪些因素？能举一个你做过的技术决策的例子吗？"**

**你听什么：**

这道题区分"写代码的人"和"能做技术决策的人"。

🟢 好的信号：能提到多个维度——业务需求匹配度、团队技术栈熟悉度、社区活跃度和文档完善度、性能表现、运维成本、可扩展性等；能举出一个具体例子，说清楚当时有哪些选项、为什么选了 A 不选 B、上线后的效果如何；决策过程中有和团队讨论、做过 POC 验证或调研。

🔴 警惕信号：只说"选最流行的"或"领导定的"；从来没有主动做过技术选型；举不出任何实际例子。

## 面试节奏建议

| 时间段 | 内容 | 目的 |
|---|---|---|
| 前5分钟 | 模块一（项目经历） | 暖场 + 验证真实性 |
| 5-13分钟 | 模块二（Java基础） | 验证技术功底 |
| 13-21分钟 | 模块三（框架与设计） | 考察工程能力 |
| 21-26分钟 | 模块四（问题排查） | 考察实战能力 |
| 26-30分钟 | 模块五（架构与软素质） | 考察综合素养 |

## 综合评判参考

| 能力维度 | 对应题目 | 权重建议 |
|---|---|---|
| 项目真实性与深度 | 题1、2 | 20% |
| Java 基础功底 | 题3、4 | 20% |
| 框架理解与工程设计 | 题5、6 | 20% |
| 线上问题排查能力 | 题7、8 | 25% |
| 架构思维与技术决策 | 题9、10 | 15% |

> **特别说明：** 考虑到你们团队需要处理 VOD 和 DFX 问题，**模块四（问题排查）的权重建议拉高**。如果候选人在第 7、8 题表现优秀，说明他有很强的线上定位能力，这在你们团队是最直接能用上的技能。反之，如果基础题答得漂亮但排查题完全没思路，要谨慎考虑。

## 万能追问句式

面试过程中随时可以用：

1. **"你能结合你的项目举个具体例子吗？"** — 区分背面试题和真实经验
2. **"如果让你重新来一遍，你会怎么改进？"** — 考察反思能力
3. **"这个方案的缺点是什么？"** — 考察思考的全面性
4. **"你说的这个，在生产环境上线后有没有出过问题？"** — 验证真实性的杀手锏
